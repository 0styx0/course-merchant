# Web (Next.js)

Guidance for working in `web/`. Repo-wide rules are in the root [CLAUDE.md](../CLAUDE.md).

This Next version differs from training data; its docs live in `node_modules/next/dist/docs/`. [AGENTS.md](AGENTS.md) (imported above, regenerated by `next dev`, don't edit) says why. Read the guide for the API you are about to use before writing code that uses it; don't survey the docs folder.

Before `yarn tsc --noEmit`, run `yarn next typegen` (Next's `PageProps`/`LayoutProps` types live in `.next/`, which can be stale or missing and cause false type errors).

Before a refactor, check which lines no test runs (whole suite, about 30 seconds): `yarn test:coverage --coverage.include=<file>`. "No files with missing coverage" means the file is fully covered.

## Shared form blocks (React Hook Form)

Create and edit forms share no value type and no state; each owns its `useForm`, resolver, defaults and type. Build shared blocks like this ([react-hook-form docs](https://react-hook-form.com/ts)):

- A field is generic: `form: UseFormReturn<T, unknown, O>` plus `name: FieldPathByValue<T, string>` (or the matching value type). The parent passes the name, so the compiler checks it.
- A section is layout only (`FormSection`, title, help) with the fields as `children`. The parent lists the fields.
- A block that needs a fixed field name (a cross-field re-check, a price row's `prices.${i}.…`) takes it as a prop.
- Shared logic is plain hooks and helpers that take `control` or `form`, not a shared form type.
- Share the zod field schemas (values), never a `CourseFormValues`-style type that both forms must fit.
- A hard-coded name inside a generic block fails `tsc`; that is the signal to pass it in. The one accepted cast is `as PathValue<T, typeof name>` on a `setValue` value, with a comment.

## Web architecture

- Layout and remaining steps are in [docs/web.md](../docs/web.md): `app/` holds routes only, `src/features/<feature>/` holds API wrappers (`<feature>.api.ts`), async `…Section` components and plain-data components.
- Data is typically fetched server-side through `src/lib/api/client.ts` (`openapi-fetch` typed by `generated.ts`, `server-only`). Each endpoint gets a wrapper in `src/features/<feature>/<feature>.api.ts` that passes the answer through `toResult()` and returns `Result<T, ProblemDetails>` (`state: "success" | "failure"`). Only a problem+json body is a failure; any other error answer throws.
- MSW handlers in `src/mocks/handlers/` (one file per endpoint, named after its operationId, typed from `operations[...]`; sample courses come from `src/mocks/fixtures/courses.ts` and problem answers from `problemResponse`) export named scenarios (`success`, `notFound`, `error`, `slow`, …). They serve three purposes:
  - Vitest — `src/test/setup.ts`; unhandled requests fail the test.
  - `yarn dev:mock` — via `src/instrumentation.ts` (Node-only startup in `src/instrumentation-node.ts`); choose the scenario in `src/mocks/node.ts`.
  - Playwright (`tests/browser`, `yarn test:browser`) — via Next's experimental test proxy: import `test` from `next/experimental/testmode/playwright/msw` and switch scenarios with `msw.use(...)`.
- `src/components/ui/` is shadcn CLI output (settings in `components.json`). Wrap primitives in `components/` or `features/` instead of editing them, and start any unavoidable edit with a `// Local change:` comment; the rule is in [docs/web.md](../docs/web.md).
