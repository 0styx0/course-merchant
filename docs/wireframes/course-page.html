Annotations

Each note names the guide section it follows and what goes wrong for the visitor without it.

  1. The buy panel sticks on desktop (§4 grid columns 9–12; §1.4 one CTA per block). It sits 96px from the top, 24px under the 72px header. Without it, a visitor who reads up to 5,000 characters of description scrolls back to the top to find the button.
  2. The fields open inside the panel, not in a dialog (§1.5 no modal; §12 #3 two fields, then the button). The price, date and time stay in view while the visitor types. Without it, a dialog hides the facts the visitor is still checking, traps focus, and shares a small phone screen with the keyboard. Fields that always show would put a form in front of every visitor who only browses.
  3. One primary button changes its label in place (§9 rule 1; §7 Button, one per block). Enroll for $99 → opens the fields, then the same slot holds Continue to payment → (Email me the link → when free). Focus moves to the Name field and the button carries aria-expanded. Without it, the panel shows two primary buttons at once and the visitor guesses which one pays.
  4. The button label carries the exact price (§9 rule 1; §8 price: $99, $49.50, Free). Without it, the phone bar, which shows no price row, hides what the visitor is about to pay.
  5. The panel reads status, time, price, button (§4 spacing: meta → price 16px, price → button 20px; §3 price style). The price sits directly above its button. Without it, the price drifts away from the action it belongs to.
  6. The course time shows first, in the course's own zone, with the zone name (§8 course time). One formatRange call prints the line. Without it, a New York evening class reads as "6 PM" and a visitor in another zone joins at the wrong hour.
  7. The visitor's time appears only when the UTC offset at the start instant differs (§8 course time). The line adds the date only when the date differs (variant c) and prints both days when the range crosses midnight (variant d). Without it, a New York visitor reads "6 PM EST (6 PM EST your time)", and a Tokyo visitor misses that the class falls on the next day.
  8. A locale changes order, clock and zone label (§8 intro: Intl in the visitor's locale, never a hand-built string). en-US prints Tue, Dec 1, 6:00 – 8:00 PM EST. en-GB prints Tue 1 Dec, 18:00–20:00 GMT-5: day before month, 24-hour clock, an offset in place of "EST". de-DE adds Uhr and spells the month Dez.. Without Intl, a hand-built string shows "12/1" to a reader who reads it as 12 January.
  9. Duration and date range come from start and end (§8 duration; date range). A one-day course shows 2 hours. A multi-day course shows Dec 1 – 3, 2026, then its first start and its last end. The API holds only a start and an end, so the page never claims daily sessions. Without it, the visitor cannot tell a two-hour evening from a three-day course.
  10. The status line shows a relative time only within 14 days (§8 relative time; §3 eyebrow in --olive). Dec 1 is 27 days after 2026-11-04, so the sample shows Starts Dec 1, 2026. Without the 14-day limit, "Starts in 27 days" becomes a soft countdown, which §1.1 rules out.
  11. The page shows no enrollment count, no seats left and no urgency (§1.1; §8 closing line; §9 rule 4). Without it, the page breaks the calm voice and quotes a number the public API never returns.
  12. A free course puts the word Free in the price slot, in plain price type (§8 price; §1.4 one accent). The gold Free badge from §7 stays off this block. Without it, the block mixes gold with the green button, which §1.4 forbids.
  13. A course in progress stays buyable and says so beside the button (§9 rule 6 limits sit next to the thing they limit). Without it, visitors wonder whether they may still join and leave.
  14. An ended course shows the pill, the sentence and one ghost link, with no price, fields or buy button (§9 rule 1 ended row; §8 ended course; §7 Badge). The date stays as a plain date. Without it, the visitor fills in a form and the server refuses it with COURSE_NOT_PURCHASABLE. If a visitor's clock or a race still reaches that refusal, the page shows the API's own message in an error alert above the form.
  15. Every field has a visible label, an example placeholder and a hint (§7 Input, label and error; §10). The hint under Email says where the link goes. Without a visible label, a placeholder vanishes the moment the visitor types and nobody remembers which field is which.
  16. Every control shows a 2px ring with a 2px offset on focus (§2 States focus; §10 focus). The Email field in 1b shows it; --ring is --primary (11.23:1 on --background). Without it, keyboard visitors lose their place.
  17. Errors say what happened and what to do, and keep the typed values (§7 Alert: errors inline above the form; §9 rule 7; §7 Input: aria-invalid, aria-describedby). 6a and 6b are separate requests: the server checks the fields before it calls the payment provider, so one response never carries both. The build shows the API's own message and title, not a fixed text. Without this, the visitor retypes a name and an email, and a red border alone tells a colour-blind visitor nothing.
  18. Loading swaps the label, replaces the arrow with a spinner and holds the width (§7 Button loading; §9 rule 1 loading strings). The fields turn read-only so their text stays readable. Without it, the button jumps in width and a second click sends a second request.
  19. The confirmation replaces the form, names the inbox and ends the flow (§9 rule 9; §9 rule 1 "after check your email: no button"). It reads the same for a free course and for a buyer who already owns the course, so the page never reveals who owns what. Focus moves to the notice. Without it, a button under "check your email" invites a second submit, and an "already owned" message leaks who is enrolled.
  20. A short "After you enroll." note sits under the button (§9 rules 3, 6, 10). It says an email arrives with the link, that Stripe takes the payment for a paid course, and that no account is needed. Without it, buyers look for a login and wait for instant access.
  21. On the phone, the buy block sits inline under the summary, and a slim bar repeats only the button once the block scrolls away (§4 stack with a 24px gap; §10 touch targets 48px; §7 Button w-full below sm). A bar alone cannot hold the date, time, price and two fields, and the keyboard would cover it. An inline block alone sends the visitor back up a long description. The bar hides while the inline block shows, so the page never carries two buttons on one screen, and the page keeps bottom padding so the bar never covers the last paragraph.
  22. The course name is the only h1; the description's headings sit below it (§10 structure; §3 below md h1 becomes the h2 step). The panel holds no headings. Without it, a screen reader outline starts at the wrong level or finds two page titles.
  23. The image keeps its 16:9 shape with square corners and an empty alt text (§5 images rounded-none; §6 a photo that repeats adjacent copy takes alt=""). The h1 right below names the course, so a screen reader that also read the name as alt text would say it twice.
  24. The panel is flat --surface-alt with --radius-lg, no shadow and no border (§1.3 flat; §5; §11 contrast). Text pairs checked in §11: --foreground 17.20:1, --muted-foreground 4.61:1, --olive 4.77:1 on --surface-alt; --input borders reach 3.19:1 on it. Without a flat panel, a shadow suggests the panel overlaps the text beside it.

Guide gaps

Each item names the default this wireframe took. Item 1 is a defect, not a gap.

  1. §8 time format throws. { timeStyle: 'short', timeZoneName: 'short' } raises a TypeError in Intl.DateTimeFormat (checked in Node 26; timeStyle cannot combine with timeZoneName). Default: { hour: 'numeric', minute: '2-digit', timeZoneName: 'short' }.
  2. §8 prints date and time separately. One formatRange call with weekday, month, day, hour, minute and timeZoneName keeps a range that crosses midnight correct. Default: that single call for the course line.
  3. §8 "always display the time zone name". Outside en-US, short prints GMT-5, not a name. Default: keep short. Alternative: long ("Eastern Standard Time") or the city.
  4. §8 "only when the zone differs" has no definition. Default: compare the UTC offset at the start instant, so Toronto and New York match.
  5. §8 relative time does not say whose calendar counts days, and the server does not know the visitor's zone. Default: the visitor's local days, so the local line and the status line render in the browser.
  6. §8 duration lists weeks and min only. Default: 2 hours, 90 min, 2 days 2 hours.
  7. §7 and §8 have no "In progress" status. Default: In progress as an eyebrow in --olive.
  8. §3 and §10: this page has no hero. The guide makes the hero title the h1 and the course title an h2. Default: the course name is the h1 at the h1 step (h2 step on the phone).
  9. §6 course imagery is 3:2, the API image is 16:9. Default: show the full 16:9 image here; cards keep cropping to 3:2.
  10. No rich-text styles. Default: description h2 uses the h3 step; h3 is body-lg weight 500; h4 is body weight 500; lists indent 24px; a quote takes a 1px --input rule; a divider is 1px --border; a link is --primary and underlined.
  11. §2 gives no value for --muted or --accent. Default: --muted oklch(0.97 0.004 106.5); --accent equals --surface-alt.
  12. §2 States have no token names for hover and pressed. Default: --primary-hover (the given value) and --primary-pressed (oklch(0.29 0.055 135), which darkens the base fill by 0.04 L; the guide does not say whether pressed starts from base or hover).
  13. §7 Badge (gold Free) clashes with §1.4. A block never uses both gold and green. Default: plain Free in the price slot.
  14. The guide has no "panel" component. Default: --surface-alt fill, rounded-lg, 24px padding, no border or shadow. Inputs use --card, which §2 reserves for "inputs and popovers only" yet §7 also gives to cards.
  15. §7 Button loading names no spinner, and §10 Motion allows only opacity and colour. Default: a 16px rotating ring, turned off under prefers-reduced-motion.
  16. Fields while a request runs. Default: readonly at full contrast, because §2 disabled (0.5 opacity) is exempt from contrast but hides what the visitor typed.
  17. The sticky phone bar has no spec. Default: --background fill, 1px --border top, 12px padding plus the safe-area inset, hidden while the inline block is in view. The sticky desktop panel sits 96px from the top.
  18. §12 #3 puts checkout on its own page; the task asks inline or dialog. Default: inline in the panel (note 2).
  19. §12 #4 adds a resend link after 60 seconds; §9 rule 9 says no button. Default: no resend on this page.
  20. §4 does not say whether the 1200px page width includes the gutters. Default: 1200px of content plus gutters, which makes seven columns exactly 680px, the prose width.
  21. Header and footer links are not listed. Default: Courses in the header; Courses and Contact in the footer (§12 #10). The hamburger is an icon button with aria-label="Menu", a string the §9 button table does not cover.
  22. Fonts. The wireframe loads no webfonts because the guide's Status list still shows self-hosting as open.

Not in the API — suggestions

None of these appear on the page. Each would need a new field or a guide string first.

  • A purchasable flag or status from the server (upcoming, in_progress, ended). The page now derives it from the visitor's clock, which can be wrong; the server refuses an ended course with its own clock.
  • Format and location (online or in person, city). §12 #8 already plans Mar 12 · Lisbon · In person and waits for this field. A buyer needs to know where to go.
  • How to join (a video link or an address for the session). Access arrives by email, so the page could say which kind.
  • Instructor (name, one line). Buyers of a live course ask who teaches it.
  • Number of sessions and length of each. §8 shows 6 sessions · 90 min each, but start and end alone cannot say it.
  • Refund and cancellation policy. The refunds flow exists; §12 #10 links it from the footer Contact. A line next to the button would settle a common doubt.
  • Contact address for the "contact us" link in the confirmation.
  • Level, prerequisites and language as short plain fields.
  • Curriculum or agenda beyond the free-form description.
  • An "Add to calendar" file. The schedule alone can generate it, but §9 fixes every button label and has no string for it.
  • Image alt text separate from the name, for images whose subject differs from the title.
  • Reviews. §9 rule 4 forbids social proof by number, so only named quotes the owner chooses could fit.
